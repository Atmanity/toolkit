# Real people and going public

## Real people

When the avatar is a real person other than the creator (a colleague, a
client, a public figure):

1. **Ask for permission** right after the first opener, before any name,
   file, generation or create: "Has Jamie agreed to have an avatar made of
   them?" If not, stop here and explain why.
2. **Keep it private or unlisted.** Don't offer public.
3. **What's allowed and what isn't:**

   | Allowed, once permission is confirmed | Never |
   |---|---|
   | Using a photo of them the creator supplies | Generating a portrait of them from a description |
   | Enhancing or restyling that supplied photo | Designing a voice to sound like them |
   | Using a voice sample of them the creator supplies | |

4. **Save the permission answer** in the iteration file.
5. **Warn before any commit** the creator asks for that the files describe a real person.

When the creator is the avatar ("it's me"), these rules don't apply, but the
photo and voice are still theirs to decide about.

## Going public

An avatar becomes public only when the creator explicitly asks.

1. Draft a title, a description of up to 280 characters, and a few tags, and
   ask the creator to approve or edit them.
2. Today the Avatar API stores only the description; it has no title or tags
   fields yet. Before publishing, tell the creator that, and ask whether to
   publish now with the description alone or wait until title and tags can be
   saved.
3. If they choose now, set the approved description and switch visibility to
   public. Keep the approved title and tags in the iteration file so they can
   be applied later.

Never make a real person's avatar public through this skill.
